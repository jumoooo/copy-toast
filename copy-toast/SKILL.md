# copy-toast — 답변의 코드 블록을 번호로 집어 복사한다

| 무엇 | 어떻게 |
|---|---|
| 언제 뜨나 | 주 루프의 답(`turn.complete`, `reason` 이 `answer`, 서브에이전트 제외)에 **복사할 블록**이 하나라도 있을 때. 사람이 있는 세션(`isInteractive`)에서만 |
| 무엇이 복사할 것인가 | 답을 쓰는 모델이 정한다(사용자 요청 「애초에 모델이 생각하고 주면 안됨?」). mod 는 코드 블록의 **말(language)** 만 본다. 말이 없거나 `text`·`md`·`output`·`log`·`tree`·`mermaid`·`diff` 같은 보여 주는 말이면 **복사할 것이 아니다** — 화면 본·예시 문구·그림이 그렇게 들어간다. `bash`·`sh`·`zsh`·`console`·`powershell`·`cmd` 같은 **셸 블록은 문장마다 한 항목** — 줄 하나가 한 문장, 끝이 `\` 인 줄·heredoc·들여쓴 줄은 앞에 붙고 빈 줄·주석 줄은 항목이 아니다. `path`·`url`·`copy` 블록은 **줄마다 한 항목** — 빈 줄과 `#` 으로 시작하는 줄은 항목이 아니고, 줄을 잇지 않는다. 그 밖의 말(`json`·`yaml`·`js`·`python`…)은 블록 하나가 한 항목. 블록 밖의 글은 빈 줄 사이에 홀로 선 명령 줄이라도 세지 않는다 |
| 모델에게 주는 규칙 | 사람이 있는 세션에서 `prompt.compose` 훅으로 시스템 프롬프트 끝에 `session` 범위 절 하나(id `copy-toast`)를 붙인다. 모델이 읽으므로 영문 네 줄이다. 사용자가 그대로 붙여 넣거나 열 것(셸 명령·이 프롬프트에 칠 슬래시 명령·파일 경로·URL·설정 값이나 조각)은 표기 있는 블록(`bash`·`powershell`·`json`·`yaml`·`path`·`url`·`copy`)에 넣고, `bash`·`path`·`url`·`copy` 블록은 한 줄에 한 항목으로 쓰고, 이름만 가리키는 것(함수·파일·플래그)은 인라인 백틱에 두고, 보여 주기만 하는 블록은 표기 없이 또는 `text` 로 쓰라는 내용이다. 엔진의 절은 건드리지 않는다. `claude -p` 처럼 그리는 화면이 없는 세션에는 붙이지 않는다. Team·Enterprise 조직의 기계에서는 엔진에 내장된 보안 기본값 `cc-plugin-sec-default@builtin` 이 사용자가 설치한 플러그인의 `prompt.compose` 훅을 건너뛰어 이 절이 모델에 닿지 않을 수 있다. 그래서 같은 규칙을 받는 사람의 `~/.claude/CLAUDE.md` 에 두게 한다(README 2절, 문구는 README 의 블록 그대로). 개인 계정에서는 훅만으로 된다 |
| 답변 쪽 번호 | `AssistantMessage` 그리기에서 블록 바로 위에 `▸ copy N`(나뉜 셸 블록은 `▸ copy N~M`, `language` 가 `ko` 면 `▸ 복사 N`) 한 줄을 넣고, 나뉜 블록은 문장 줄 앞에 `(N) ` 을 붙인다 — 그려지는 글만 바뀌고 저장된 메시지는 그대로(ctrl+o 에도 없다). 복사는 저장된 글에서 하니 `(N) ` 은 붙어 가지 않는다. 답이 여러 토막으로 그려져도 번호가 이어진다(토막이 답의 어디인지 찾아 앞 토막의 항목을 함께 센다). 같은 파일·폴더를 가리키는 항목은 같은 번호를 받는다(열기 행) — 앞 토막의 항목과 같은 파일이면 그 번호이고, 번호가 띄엄띄엄인 블록 위에는 `▸ copy 1, 3` 처럼 적는다 |
| 토스트 | 프롬프트 위 띠(`AbovePrompt`) 오른쪽 끝에 **항목마다 한 장** — 둥근 테두리 한 줄 상자 `번호 · 블록 첫 줄 미리보기 · [ Copy ]`(`ko` 면 `[ 복사하기 ]`), 위에서 아래로 쌓인다. 폭은 64칸까지. 레이아웃은 엔진(Ink)에 맡긴다 — 테두리는 `borderStyle: round`, 미리보기는 `wrap: truncate` 로 엔진이 자른다. 우리가 칸을 세어 맞추던 판은 「—」「…」 같은 애매한 폭 글자에서 줄이 어긋났다(사용자 요청). 미리보기의 그런 글자는 ASCII 로 바꾼다. 다른 플러그인의 띠 위에 얹고, 설문(`hasSurvey`)이 띠를 쥐면 비킨다 |
| 열기 | 항목 글이 경로 꼴(`/…`·`~/…`·`C:\…`·`\\wsl.localhost\…`·`file://…` 주소)이고 **디스크에 있으면** 복사 버튼 왼쪽에 아이콘 버튼 `[📂]` 한 칸. 누르면 그 폴더를 파일 탐색기로 띄운다. 파일이면 든 폴더를 열고 그 파일을 선택·포커스한다(`hooks/open_dir.js`). WSL·Windows 에서는 먼저 열린 탐색기 창을 `hooks/open_focus.ps1`(PowerShell, `Shell.Application` 의 창 목록)로 보고, 그 폴더를 보는 창이 이미 있으면 새로 띄우지 않고 그 창을 앞으로 올린다(사용자 요청 2026-10-29). 없으면 `explorer.exe <폴더>` 또는 `explorer.exe /select, <파일>` 로 새 창을 띄운다 — WSL 은 경로를 `wslpath -w` 로 바꾼다. 그 밖은 `xdg-open`·`open` 으로 든 폴더를 연다(파일 선택은 없다). 연 결과는 toast 한 줄로 보인다 — `opened: <경로> (앞으로)` · `(이미 열림)`(창은 있으나 올린 뒤에도 앞 창이 그 창이 아니었다) · `(새 창)`, 파일이면 뒤에 `, 파일 선택`. 이 낱말은 `language` 옵션과 상관없이 한국어다. 장은 그대로 남아 복사도 이어서 된다. 세션이 WSL 이면 `C:\…` 는 `/mnt/c/…` 로, `\\wsl.localhost\<배포판>\…` 는 `/…` 로 바꿔 찾고, Windows 세션이면 `/mnt/c/…` 는 `C:\…` 로 바꾼다(`/home/…` 은 어느 배포판인지 몰라 열지 않는다). `~` 는 `HOME`(Windows 는 `USERPROFILE`). `file://` 주소는 퍼센트 꼴(`%20`·한글)을 풀어 경로로 바꾼다 — `file:///C:/…` 는 `C:\…`, `file:///mnt/c/…`·`file:///home/…` 은 그 경로, `file://wsl.localhost/<배포판>/…` 는 `\\wsl.localhost\<배포판>\…`. `file://` 이 아닌 URL·슬래시 명령·없는 경로·셸 문장에는 버튼이 없다 — 있는지는 `$.fs.stat` 이 답한다(`hooks/locate.ts`). 못 열면 toast 한 줄. **같은 파일·폴더는 장 하나**(사용자 요청 2026-10-30)이고, 두 번 합친다. 먼저 디스크에 묻지 않고 글로 합친다 — `file://` 주소의 퍼센트 꼴을 풀고 `C:\…`·`/mnt/c/…`·`\\wsl.localhost\<배포판>\…` 를 한 꼴로 맞춰(드라이브 쪽은 대소문자를 가리지 않는다, `toast.ts` 의 `pathKey`) 같으면 첫 항목 자리에 한 장으로 합친다. 디스크에 없는 항목도 이 단계에서는 합친다. 답변 쪽 번호도 이 결과를 쓰므로 장 번호와 같다. 다음은 디스크가 답한 실제 자리(`$.fs.stat` 의 `realPath`, 없으면 이 기계의 경로)로 한 번 더 합치고 장 번호를 다시 매긴다 — 링크, 그리고 `~/…` 와 `/home/…` 처럼 글로는 다른 꼴이 여기서 합쳐진다. 이 드문 경우에만 답변 쪽 번호와 장 번호가 어긋날 수 있다. 합친 장에 보이는 글과 복사할 글은 Windows 쪽 꼴(`C:\…`·`\\…`)이 있으면 그것, 없으면 첫 항목의 글이다 |
| 복사 | 버튼(`[ Copy ]`, `ko` 면 `[ 복사하기 ]`)을 누르면 그 블록 본문 전체가 `$.ui.copy` 로 그 화면의 클립보드에(`/copy` 와 같은 길 — 터미널 도구 또는 OSC 52). 그 장만 `Copied`(`ko` 면 「복사 완료」)로 바뀌고 0.9초 뒤 밀려 나간다. 다른 장은 남는다. 못 하면 toast 한 줄로 이유 |
| 사라지는 때 | 그 장을 복사했을 때 · 사용자가 다음 입력을 했을 때 남은 장 전부(`prompt.submit` 의 `origin.kind` 가 `composer` — 배경 작업 알림·다른 세션의 글은 아니다) · 새 답이 왔을 때(새 장들로 바뀐다). 번호는 다음 답이 올 때까지 답변에 남는다 |
| 스르륵 | 40ms 마다 한 그림, 들어올 때 6그림·나갈 때 5그림, 다음 장은 두 그림 늦게. 보이는 칸만큼의 창(`overflow: hidden`)으로 잘라 장이 오른쪽 끝에서 밀려 들어오고 나간다, 반쯤 전엔 흐리게. 움직이는 동안은 버튼 자리가 글자뿐이라 누를 수 없다 |
| 색 | 기본(`colors` 가 `theme`)은 엔진의 테마 키만 쓴다 — 테두리 `suggestion`, 번호·올렸을 때 `claude`, 글 `text`, 움직이는 중의 버튼 글 `inactive`, 버튼 바탕 `subtle`. 밝고 어두운 구분은 사용자의 테마가 맡는다. `palette` 옵션이면 금→장미 팔레트의 hex — 테두리·버튼 바탕은 코랄의 보색인 청록(`#2b7a78`, 밝은 테마는 `#c4e4e2`), 번호는 코랄, 올리면 장미이고, 밝은 테마인지는 `$.config.list()` 의 `theme` 행으로 가른다. 완료 글은 두 경우 모두 엔진의 `success` |
| 상태 | `$.state` 두 키 — `items`(장들, 각자 `phase` `in`·`show`·`done`·`out` 와, 열 폴더가 있으면 `dir` 를 쥔다. 다 나가면 빈다) · `answer`(번호 맞출 답 원문). 장마다의 그림 수와 시계는 모듈 변수 |

## 옵션

`plugin.json` 의 `userConfig` 둘이다. 엔진이 `register(on, options)` 로 넘겨 준다.

| 옵션 | 값 | 기본 | 하는 일 |
|---|---|---|---|
| `language` | `en` · `ko` | `en` | 화면 글. `en` 은 `▸ copy N`·`Copy`·`Copied`, `ko` 는 `▸ 복사 N`·`복사하기`·`복사 완료` |
| `colors` | `theme` · `palette` | `theme` | `theme` 은 엔진 테마 키만 써서 사용자의 테마를 따르고, `palette` 는 금→장미 hex 로 그린다 |

바꾸는 법은 JSON 객체 하나를 표준 입력으로 넣는 것이다. 넣지 않은 옵션은 앞의 값을 지킨다.

```bash
echo '{"language":"ko","colors":"palette"}' | claude plugin configure copy-toast@skills-dir --values-stdin
```

지금 값과 비어 있는 옵션은 `claude plugin configure copy-toast@skills-dir` 로 본다.

## 켜는 법

`~/.claude/skills/copy-toast/` 에 있으므로 다음 세션부터 `copy-toast@skills-dir` 로 자동 적재된다. 지금 세션은 `/reload-plugins` — 도중에 붙으면 `session.start` 가 없으므로 사람이 있는지는 `$.session.surfaces()`(그리는 화면이 하나라도 있나)로 가른다.

## 검사

```bash
cd ~/.claude/skills/copy-toast
claude plugin validate .
claude plugin test .                          # 23건 — 아래 목록
node hooks/open_dir.js --self-test            # 열기 스크립트 25건(플랫폼별 명령·인자 오류·ENOENT·파일 선택·열린 창 가름·결과 한 줄)
npx -y -p typescript tsc -p tsconfig.json     # 먼저 .claude-plugin/types/ 를 만들어야 한다 — 아래
```

시험 스물세 건(`tests/copy-toast.test.ts`). 앞의 여덟 건은 `language=ko`·`colors=palette` 옵션으로 돈다.

1. 장이 밀려 들어오고 번호·미리보기·버튼이 그려지며, 누른 장만 완료 뒤 나간다
2. 답변의 블록 위 번호 — 뒤 토막만 그려져도 번호가 이어진다
3. 다음 입력이면 남은 장이 나간다(배경 알림은 아니다) · 블록 없는 답이면 장이 없다
4. 사람 없는 세션(`claude -p`)·서브에이전트의 턴에는 그리지 않는다
5. `/reload-plugins` 로 도중에 붙어도 화면이 있으면 뜬다
6. 항목 수에 상한이 없다(셸 열두 문장)
7. 울타리 밖의 홀로 선 명령 줄은 항목이 아니다 — 표기 있는 블록만 센다
8. `! 명령` 줄은 홀로 서면 항목이 아니고, `copy` 블록에 넣으면 `!` 까지 한 장
9. 옵션 없음 — 영어 글이고 트리에 hex 가 없다
10. `colors=palette` 면 hex 로 그린다
11. `path`·`url`·`copy` 블록은 줄마다 한 항목 — 빈 줄과 주석 줄은 빼고 줄을 잇지 않는다
12. 홀로 선 영어 명령 줄(`git push origin main`·`git add .`·`cd ..`)도 항목이 아니다
13. 사람이 있는 세션 — 시스템 프롬프트 끝에 규칙 절이 붙고 엔진의 절은 그대로다
14. 사람이 없는 세션(`claude -p`)·화면이 없는 세션에는 규칙 절이 없고, 도중에 붙어 화면이 생기면 붙는다
15. 열기 버튼 — 디스크에 있는 경로(폴더·파일·`C:\` 꼴·`~`)에만 `📂` 가 복사 버튼 왼쪽에 붙고, 누르면 `open_dir.js` 에 그 폴더(파일은 그 파일)를 준다. URL·슬래시 명령·없는 경로·셸 문장엔 없고, 장은 남아 복사도 된다. 연 결과와 못 연 이유는 toast
16. 열기 버튼 — Windows 세션이면 `/mnt/c/…` 는 `C:\…` 로, `~` 는 `USERPROFILE` 로 바꾸고, `/home/…` 은 열지 않는다
17. 열기 버튼 — 파일 항목은 파일 경로를, 폴더 항목은 폴더 경로 하나만 `open_dir.js` 에 넘긴다
18. 열기 버튼 — `open_dir.js` 가 찍은 마지막 줄(`opened: … (앞으로)` 등)을 그대로 toast 로 보인다
19. 같은 파일은 한 장 — Windows 경로와 그 `file://` 주소가 번갈아 온 여섯 항목이 세 장(1~3)이 되고, 보이는 글과 복사는 Windows 경로, `📂` 는 그 파일을 넘긴다
20. `file://` 주소만 있어도 `📂` — `%20`·한글 퍼센트 꼴을 풀어 디스크에 묻는다. 주소가 먼저 와도 합친 장은 Windows 경로를 보이고, `https` 는 디스크에 묻지 않는다
21. 같은 폴더도 한 장 — `/home/…`·`~`·`\\wsl.localhost\…`·`file://` 꼴 다섯이 하나가 되고, 다른 파일 둘은 둘, 실제 자리(`realPath`)가 같은 링크는 합친다
22. 답변 쪽 번호 — 캡처의 여섯 항목은 `▸ 복사 1`~`▸ 복사 3` 만 붙고 주소 블록은 짝인 경로와 같은 번호, 뒤 토막만 그려져도 앞 토막의 같은 파일 번호를 받는다
23. 답변 쪽 번호 — 경로와 그 `file://` 주소는 한 번호, 다른 파일 둘은 두 번호(디스크에 없어도 글로 가른다)

`tsc` 가 읽는 타입(`.claude-plugin/types/`)은 Claude Code 빌드마다 달라 함께 두지 않는다. Claude Code 에 내장된 `plugin-authoring` 스킬로 이 폴더에 다시 만든 뒤 `tsc` 를 돌린다. `claude plugin test` 와 `claude plugin validate` 는 타입 없이 돈다.

## 한계

- 복사할 것은 말이 있는 코드 블록만이다. 인라인 코드(`` `x` ``)·표·목록·말 없는 블록·블록 밖의 명령 줄은 세지 않는다. 모델이 규칙 절을 따르지 않고 명령을 블록 밖에 쓰면 그 명령은 띠에 뜨지 않는다.
- 셸 문장 나누기는 줄 단위다. 한 줄에 `;` 나 `&&` 로 이은 명령은 한 항목이고, 여러 줄로 쓴 `if`/`for` 블록은 들여쓰기가 없으면 줄마다 갈린다.
- 엔진의 토스트(`$.ui.toast`)는 글 한 줄이라 버튼을 못 싣고, 누르면 사라질 뿐 우리 코드에 오지 않는다. 그래서 「토스트」는 프롬프트 위 띠에 그린 장들이다 — 오른쪽 끝에 쌓여 토스트처럼 보이지만 오른쪽 위에 떠 있지는 않다.
- 버튼의 `[ ]` 테두리는 엔진이 그린다. 미리보기 칸은 그 테두리를 4칸으로 치고 남긴 폭이고, 넘치면 엔진이 자르므로 상자 선은 어긋나지 않는다.
- OSC 52 는 결과를 돌려주지 않아, 터미널이 그 신호를 버려도 완료 글(`Copied`, `ko` 면 「복사 완료」)로 보인다(엔진이 그렇게 답한다).
- `claude -p` 와 서브에이전트의 턴에는 아무것도 하지 않는다.
- 열기 버튼은 폴더를 띄우고 파일은 그 안에서 선택할 뿐이다 — 파일을 그 앱으로 여는 것은 아니다. 열린 창 확인과 앞으로 올리기는 PowerShell 을 한두 번 띄우므로 누르고 1~2초 뒤에 창이 온다(2026-10-29 실측 0.8~2.1초). 디스크에 묻는 것은 답이 끝날 때 한 번이라, 그 뒤 만들어진 경로에는 버튼이 없다. 네트워크 경로(`\\server\…`)는 열지 않는다.
